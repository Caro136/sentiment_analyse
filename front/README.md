# 智能舆情分析平台 · 前端

Vue 3 + TypeScript + Vite 单页应用。承接 `docs/智能舆情分析平台-设计规格.md` 的 T-06 与前端模块划分。

## 快速开始

```bash
cd front
npm install            # 已配置国内镜像（.npmrc）

npm run dev            # 开发服务器 http://localhost:5173
npm run type-check     # 类型检查（不改动产物）
npm run build          # 类型检查 + 生产构建，输出 dist/
npm run preview        # 预览构建产物
```

开发服务器已把 `/api` 代理到 `http://localhost:8000`，因此本地起后端后无需处理跨域。

## 与后端的约定

| 约定 | 说明 |
|------|------|
| 接口前缀 | `/api/v1`（在 `client.ts` 的 baseURL 中统一配置） |
| 健康检查 | `/healthz`、`/readyz` 在根路径，**不在** `/api/v1` 下，请求时显式覆盖 baseURL |
| 响应解包 | 拦截器已返回 `data`，调用方直接拿业务数据，不必写 `res.data` |
| 错误处理 | 失败抛 `ApiError`（含 `code` / `trace_id`），401 或 `AUTH_*` 自动跳登录 |
| 枚举取值 | 必须与 `engines/contracts/enums.py` 一致，写错字面值不会报错但筛选恒为空 |
| 字段命名 | 后端接口统一用 snake_case（`content_uid` / `risk_level`），前端不做驼峰转换 |

> `/healthz` 与 `/readyz` 的路径差异是个容易踩的点：它们注册在应用根路径，
> 而业务接口在 `/api/v1` 下。axios 的 baseURL 会无条件拼接，所以健康检查必须显式传 `baseURL: ''`。

## 下钻参数（跨页面约定）

大盘的每张图表都能点击下钻到研判工作台（设计规格 3.4），参数名是**两个页面之间的契约**：

| 参数 | 取值 | 来源 |
|------|------|------|
| `topic_id` | 主题业务ID | 大盘的主题筛选（跳转时自动带上） |
| `sentiment` | `positive` / `neutral` / `negative` | 情感环形图点击扇区 |
| `source_type` | `social_media` / `short_video` / `news_portal` / `industry_forum` | 信源分布点击某一行 |
| `risk_level` | `S` / `A` / `B` / `C` | 指标卡「S/A 级事件」点击 |
| `keyword` | 任意词 | 词云点击某个词 |
| `start_time` / `end_time` | Unix 秒 | 趋势图点击某个时间桶 |
| `from` | `dashboard` / `alert` | 来源标记，工作台可据此区分入口 |

除筛选条件外，还有**一类指定处置对象的参数**（告警行的「处置」按钮）：

| 参数 | 取值 | 来源 |
|------|------|------|
| `event_id` | 事件业务ID | 告警行的「处置」——直接切到该事件而不筛选内容 |
| `alert_id` | 告警业务ID | 同上；开单时提交给后端，工单据此记住来源告警 |

这两类参数的生命周期不同，因此在 `WorkbenchView` 里分开存放：筛选由用户操作驱动，
而 `alert_id` 属于某个具体事件——**用户手动切换事件即作废**（否则新事件开出的工单会挂上
一条无关的告警，比丢掉关联更糟）。两者都在 `syncFiltersToQuery()` 里原样写回 URL，
因为同步筛选用的是 `router.replace`，漏掉它们会让关联在改一次筛选后悄悄消失。

这些取值**与后端筛选参数同名同值**，工作台拿到后可以直接透传给 `/api/v1/contents`，
不需要再做一层翻译（翻译层是错位的常见来源：前端写 `shortvideo`、后端要 `short_video`，
筛选恒为空且不报错）。

### 工作台的两处实现约定

1. **筛选状态同步到 URL**（`router.replace`，不堆历史）：刷新、分享、从大盘下钻后再返回，
   筛选都不会丢。切换「同一组件收到新 query」时会重新读参数（见 `WorkbenchView` 的 watch）。
2. **跨区高亮用一条 `activeUid`**：卡片 ↔ 时间线节点 ↔ 聚类成员任一处点击，另两处同步高亮。
   但时间线/聚类覆盖的是**事件的全部内容**，而卡片流受筛选与分页限制——当选中内容不在当前
   列表里时，卡片流顶部会**如实提示**「该内容来自时间线或聚类，不在当前筛选结果中」，
   而不是让高亮看起来失效（这一步是浏览器实测发现的）。
3. **内容详情做成抽屉而不是右侧标签页**（原型是标签页）：读全文需要宽度，且时间线要留在
   视野里对照。抽屉去掉了默认头部（标题行自带信息），因此**必须自己保留关闭按钮**——
   只靠点遮罩或 ESC，用户会以为关不掉（截图核对时踩过）。

### 图表封装（`utils/chart.ts`）

`useChart(container, { onClick })` 统一处理三件每张图都要做的事：初始化与销毁
（不销毁会泄漏 canvas）、容器尺寸变化时 resize（ECharts 只在初始化时读一次尺寸，
不 resize 的图在侧边栏折叠后会错位）、数据更新走 `setOption` 而不是重建实例。

**点击下钻必须用这个 `onClick`（ECharts 事件），不要在外层 div 上监听 DOM 点击**：
图表画在 canvas 上，DOM 事件拿不到「点了哪个扇区」——用 `event.target.textContent`
猜文本会在部分浏览器与缩放下完全失效（实现时踩过）。

### 热词云的实现方式

词云用**加权标签云**（CSS 字号映射权重），不是 canvas 词云：
排行靠前的词需要可点击、可悬停看来源与权重、可被读屏识别，标签云天然支持这三件事；
且「星耀XPhone15」这类长词放进 canvas 词云会被压得看不清。
需要 canvas 效果的话可接 `echarts-wordcloud` 替换这一块，数据结构无需改动。

### 处置协同区（T-31，`components/workbench/DisposalPanel.vue`）

工单是挂在**事件**上的，因此这块只在工作台选中事件后出现（没有事件就没有处置对象）。

| 需求 | 落点 |
|------|------|
| FR-49 状态流转 | 目标状态的可选项来自后端 `allowed_transitions`，**前端不复制一份状态机** |
| FR-50 处置批注与轨迹 | 只传 `note` 即追加批注（`comment` 轨迹）；轨迹按时间正序只增不改 |
| FR-51 回应草案 | 生成（不落库）→ 人工编辑 → 采纳（写进工单 + `draft_adopt` 轨迹）→ 可再编辑再采纳 |

四条实现约定：

1. **状态机不写第二份**。可流转目标由后端 `allowed_transitions` 给出，前端只按角色
   过滤掉「关闭」类动作（`ticket:close` 仅公关）。前后端各存一份状态机的必然结局是漂移：
   前端放行了、后端 409，或者反过来漏拦。
2. **转入「跟踪中」即认领，并把承办人一并落库**。后端把这一步记成 `claim` 轨迹，
   但只有传了 `assignee_id` 才写承办人——不传就会留下「轨迹写着认领、承办人是空」的矛盾，
   而处置最忌责任人不明。`DisposalPanel` 因此在提交时附带当前用户为承办人。
3. **生成与采纳分成两步**：生成是探索（可能反复试），采纳是决策（进审计）。
   因此生成**不落库**，采纳才写进 `ticket.response_draft`；再次采纳是**追加一版**而不是覆盖，
   旧版本留在处置轨迹里。工单上已采纳的版本必须能再看一眼（「查看」）与接着改（「继续编辑」）——
   只留一句 toast 的话，用户会不确定自己到底存了什么。
4. **管理员看不到这块区域**（显示一句说明而不是只读表单）：PRD 第 2 章把他排除在处置之外，
   后端也没有相应权限。给只读框只会让人以为自己能用。角色判断同样一律走后端权限矩阵的
   前端副本（`auth.hasRole`），不写死字符串比较。

**与大盘的衔接**：告警行的「处置」带着 `event_id` + `alert_id` 跳工作台（参数见上），
开单时把 `alert_id` 提交给后端——工单因此能回答「这条舆情为什么被处理」。
这条链路是 T-34 端到端演示（监测→预警→研判→处置→报告）的中间一段。

> PRD 7.2 的线框图把「风险复核」画在处置协同区那一行，实现时挪到了上面的**事件分析与溯源区**：
> 它作用于**事件**（FR-24）而不是工单，且仅分析师可做，与「处置动作」（分析师 + 公关共有）
> 不是同一类权限域。放进处置区会让两种角色在同一块表单里各看到一半可用的控件。

### 报告中心（T-32，`views/ReportsView.vue`）

| 需求 | 落点 |
|------|------|
| FR-57 列表与筛选 | 类型（专项/周期）、主题、状态 + 分页；**筛选走服务端**（见下） |
| FR-58 一键生成 | 对话框选目标 → `POST /reports` 立即 202 → 选中新报告 |
| FR-60 在线预览 | `ReportPreview` + `utils/markdown.ts`（Markdown 子集，模板渲染） |
| FR-61 导出 | Markdown / HTML 下载；**PDF 走浏览器打印**（D-07） |
| FR-62 进度与失败 | SSE 进度条 + 3 秒轮询到终态；失败给原因与「用同一目标重试」 |

四条实现约定：

1. **SSE 管「看得见在动」，轮询管「知道结束了」**。报告生成实测 53~60 秒，
   而进度事件只有 0/50/100 三档（后端在开始与结束时各发一次）——光看进度条会长时间停在
   50%，像卡住了。因此进度条配一句阶段文案（`realtime.progressMessage[report]`），
   同时每 3 秒拉一次详情：**成没成、失败原因是什么，以库里的状态为准**，
   SSE 断线也不会让页面永远停在「生成中」。
2. **类型筛选必须在服务端做**。类型是 PRD 7.3 页面上的一级分类，只筛当前页会让
   第二页的同类报告凭空消失——看着对、实际不全。为此 T-32 给 `GET /reports`
   补了 `report_type` 参数（后端同步改了 schema/router/service/仓储与测试）。
3. **PDF 用服务端渲染的 HTML 打印，不 `window.print()` 本页**（D-07）。
   服务端那份 HTML 是自包含的、样式面向 A4 优化（章节不跨页），而本页预览是
   Markdown 子集的排版——打印出来的和下载到的不一致，比「多开一个标签页」更让人困惑。
   弹窗被拦截时退回「下载 HTML + 提示手动打开」，不静默失败。
4. **预览不用 `v-html`**：报告正文引用了用户原文（微博、论坛），
   `v-html` 等于把外部文本当代码执行。这里解析成块结构后用模板渲染，
   插值自动转义，注入面为零；代价是只支持 Markdown 子集（标题/列表/表格/引用/强调/代码），
   遇到不认识的行按普通段落渲染，不丢内容。

> 正文自带 `# 一级标题` 时不再重复显示库里的 `title`：实测模型输出的首行就是
> 「# 某某舆情研判报告」，两个都渲染会在报告顶部出现两个几乎一样的标题。

### 监测配置（T-33，`views/ConfigView.vue`）

| 页签 | 需求 | 写权限 |
|------|------|--------|
| 监测主题 | 主题元信息 / 词包 / 启用通道（FR-06~09） | 分析师（**限本人主题**）与管理员 |
| 信源通道 | 启停、采集频率、回溯窗口、连通性自检（FR-11~13） | 仅管理员 |
| 预警规则 | 阈值、等级、敏感词库、补扫（FR-52/53） | 仅管理员 |
| 通知渠道 | 邮件与站内通知的**只读**状态（FR-54） | — |
| 运行配置 | 白名单内参数热更新（FR-53） | 仅管理员 |

五条实现约定：

1. **权限按页签分层，且以「不显示」表达而不是禁用**。公关根本进不了这一页
   （路由 `meta.roles`）；分析师看不到「预警规则」「运行配置」两个页签——因为后端连读
   都不给（`alert_rule:write` / `config:read` 只给管理员），给一个进去就 403 的页签
   只会让人以为系统坏了。词包页签对非本人主题显示只读并说明原因。
2. **词包是「全量替换」，权重必须原样提交**。词包接口的语义是整份配置，因此编辑期
   持有后端返回的完整词条（含 0.7 / 0.9 / 1.0 这些权重）并整份提交——
   漏掉权重不会「保持不变」，而是把整组词静默重置成 1.0。
   词包编辑器因此用表格（词 + 权重 + 删除）而不是标签云：标签里塞不进权重输入框。
3. **三个写路径分开**：元信息、词包、启用通道各有保存按钮与接口。合成一个「保存」
   会让「只改了名字却把词包也提交一遍」变成默认行为。
4. **通知渠道只读，且明说原因**：SMTP 主机 / 账号 / 授权码属于密钥与部署配置，
   不在运行配置白名单内（设计规格 8.1 的刻意约束，`ConfigWhitelistTest` 用正则钉死）。
   这一页展示 `/readyz` 的能力就绪状态与最近告警的投递结果，改配置走 `.env` + 重启。
5. **「运行配置」是本页第五个页签**（PRD 7.4 只画了四块）：FR-53 的白名单热更新
   没有别的落点，而它调的正是监测相关参数。它与其它页签的区别也标在界面上——
   **只作用于进程内单例、不写 `.env`、重启回落**，需要持久化的阈值请用「预警规则」
   （落在数据库）。

> 分析师账号在演示数据里看不到可写的主题（三张主题都属同一个负责人账号），
> 因此分析师进入本页时词包编辑器是只读的——这是**权限矩阵的正常结果**
> （`TOPIC_WRITE` 对分析师是 `OWNED_ONLY`），不是页面坏了。演示配置变更请用管理员。

**「主题关键词」的推导时机**（界面上写了同一句，因为很容易误解）：建主题时留空会**立即**
按词包推导；而**编辑**时清空只是把字段置空，推导发生在**下一次保存词包**时
（当前值为空或等于旧推导值才跟随）。因此清空后若不再保存词包，该主题就召不回任何内容——
接入层靠这个字段做归属匹配。这条是实机验证出来的（清空 → 再保存词包 → 值回到原推导值）。

## 开发须知

1. **前端守卫挡不住直接调接口**。`meta.roles` 只是体验优化，真正的权限控制必须在后端独立鉴权（设计规格 8.1）。
2. **不要在 `api/modules.ts` 里写猜测的接口**。路径写错前端只会拿到 404，排查成本远高于等后端接口就绪。
3. **菜单不要单独维护**。`DefaultLayout` 从路由表派生菜单，避免「菜单有但路由没配」这类不一致。
4. **图表配色统一取 `styles/main.css` 的设计令牌**。风险等级与情感倾向的颜色会出现在大屏、卡片、标签、图表各处，各自定义必然出现同一等级颜色不一致。
5. **下载类请求走 `downloadFile()`，不要用 `http.get`**。`http.get` 走响应解包、只留 `data`，
   而文件名在 `Content-Disposition`、后端提示在 `X-Export-Hint`（例如「PDF 请用浏览器打印」）。
   对应地，`client.ts` 的响应拦截对 `responseType: 'blob'` 保留完整响应，
   并且**错误响应体也会被当 Blob 解析一次**——不然下载失败时只能给出
   「请求失败（HTTP 422）」，而 422 恰恰是那句需要原样转告用户的说明。
6. **外部文本一律不 `v-html`**。报告预览已经按这条实现（`utils/markdown.ts` + 模板渲染），
   新增任何展示「用户原文/模型输出」的地方都照此办理。
