# 评测集

对应 PRD 决策 **D-02**：评测集由项目组基于模拟多源数据自行构造并人工标注，随项目交付，
作为情感模型与风险分级规则调整后的**回归测试基线**。

| 文件 | 规模 | 对应成功标准 |
|------|------|-------------|
| `sentiment_eval.jsonl` | 330 条 | SC-02：情感倾向识别准确率 ≥ 85% |
| `risk_eval.jsonl` | 100 条 | SC-03：风险等级判定与人工标注一致率 ≥ 80% |

> 由 `python data/generator/generate.py` 随数据集一并产出，不单独生成。

---

## 一、为什么困难样本要占两成以上

如果评测集只由「太离谱了，这种店就该停业整顿」→ 负向 这类样本构成，
准确率会虚高到 95% 以上，但**这个数字毫无意义**——它衡量不出模型对真实舆情文本的处理能力。

因此本评测集**强制纳入 ≥60 条困难样本**（实际 67 条，占 20%），覆盖：

| 困难类型 | 示例 | 为什么难 |
|---------|------|---------|
| 反讽 | 「星耀这散热真是绝了，冬天都不用买暖手宝了，谢谢星耀帮我们省钱」 | 通篇褒义词，实际是强烈不满 |
| 混合情感 | 「屏幕和影像确实没得挑，就是这发热让我有点犹豫要不要退」 | 正负并存，需判定主导倾向 |
| 纯事实陈述 | 「星耀科技于今日发布说明，称将通过系统更新优化功耗调度策略」 | 无情感词，中性但含负面话题 |
| 表情符号主导 | 「🤢🤢🤢」 | 无文本，只能靠表情语义 |
| 超短文本 | 「退了」「劝退」「拉黑」 | 上下文信息极少 |
| 中性疑问 | 「请问这个测试的环境温度是多少度」 | 疑问句易被误判为质疑 |
| 正向含负面词 | 「别再黑星耀了，我用了两周一次过热关机都没出现过」 | 含否定词与负面话题，实为正向辩护 |
| 转述他人观点 | 「转载一下老张的结论，具体数据大家自己判断，我不做评价」 | 转述者本身无倾向 |

困难样本的 `gold_sentiment` 由人工逐条给定，并在 `note` 字段写明判定理由，可复核、可争议。

## 二、`sentiment_eval.jsonl`

```json
{
  "id": "se_0076",
  "text": "打游戏也不至于烫到不能碰！",
  "source_type": "行业论坛",
  "scenario": "consumer_electronics",
  "gold_sentiment": "positive",
  "gold_sentiment_label": "正向",
  "gold_emotion": "",
  "difficulty": "normal",
  "note": ""
}
```

| 字段 | 说明 |
|------|------|
| `text` | 待判定文本（含话题标签等噪声，与真实数据形态一致） |
| `source_type` | 来源信源（社交媒体 / 短视频 / 新闻门户 / 行业论坛） |
| `scenario` | 所属场景 |
| `gold_sentiment` | 标准答案：`positive` / `neutral` / `negative` |
| `gold_emotion` | 负向细分情绪：`愤怒` / `失望` / `恐慌` / `质疑`；正向与中性为空串 |
| `difficulty` | `normal` / `hard` |
| `note` | 困难样本的判定理由，简单样本为空 |

**分布**：正向 110 / 中性 110 / 负向 110（严格均衡），其中困难样本 67 条。

**使用建议**：分别统计 `difficulty=normal` 与 `difficulty=hard` 的准确率。
两者的差距比总体准确率更能反映模型的实际水平。若简单集 95% 而困难集 55%，说明模型学到的只是表层线索。

## 三、`risk_eval.jsonl`

```json
{
  "event_id": "re_0002",
  "scenario": "catering_food_safety",
  "scenario_title": "味鲜居连锁门店后厨卫生问题曝光",
  "window_start": "2026-10-13 08:00:00+08:00",
  "window_minutes": 60,
  "volume": 30,
  "negative_ratio": 0.83,
  "kol_involved": true,
  "sensitive_hit": true,
  "event_desc": "……",
  "gold_risk_level": "S",
  "gold_intensity_factors": {
    "intensity_index": 0.91,
    "negative_ratio": 0.83,
    "volume": 30,
    "volume_score": 0.75,
    "kol_involved": true,
    "sensitive_hit": true
  },
  "note": "由时间窗聚合指标按 PRD 附录 B.2 规则标注"
}
```

标注方式：按场景时间线做 60 分钟滑窗聚合（步进 30 分钟，防漏掉峰值），
对每个窗口计算指标后套用**烈度指数规则**得到等级。窗口时长取 60 分钟，
与 PRD 的「单小时负向声量环比激增」预警规则对齐。

烈度指数计算（对应 PRD FR-22 / FR-23）：

```
intensity = 0.50 × 负向占比
          + 0.30 × min(声量 / 40, 1)
          + 0.12 × (是否有高权重账号发声)
          + 0.15 × (是否命中高危敏感话题)

S: intensity ≥ 0.72    A: ≥ 0.58    B: ≥ 0.40    C: < 0.40
```

采用**加权连续评分而非硬阈值组合**，是为了避免「8 条声量、75% 负向」这类小规模波动
被判为 S 级（极高危）——绝对声量阈值在样本量小时尤其不可靠。

标注时还做了两项清洗：
- 过滤烈度 < 0.15 的窗口（毫无区分度，闭眼选 C 就能对，只会让分数虚高）；
- 保证 3 个场景 × 4 个等级都有覆盖，避免样本被内容量最大的场景淹没。

## 四、使用

评测集为纯 JSONL，无依赖，读取方式：

```python
import json

records = [json.loads(line) for line in open("data/eval/sentiment_eval.jsonl", encoding="utf-8")]
hard = [r for r in records if r["difficulty"] == "hard"]
```

评测集**不参与任何训练**，仅作回归基线。调整 Prompt、更换模型或修改烈度指数权重后，
都应重跑这两个评测集并对比结果。

## 五、注意事项

1. **正式评测请用 `--scale prd` 生成的数据集**。
   风险评测集的等级分布依赖候选窗口数量：small 档 S 级仅 5 条（A 13 / B 33 / C 49），
   prd 档可达 S 24 / A 24 / B 25 / C 27。S 级样本过少时，高等级判定的评测结果不具代表性。
2. **评测集随数据规模变化**。同一次 `--scale` 下的评测集是稳定的（种子固定），
   但切换规模后样本会重新抽样，跨规模的结果不可直接比较。
3. **风险等级标签是规则推导的，不是真人标注的**。规则本身可复核
   （见 `data/generator/eval_builder.py` 的 `_judge_risk`），
   但如果业务方对烈度权重的判断与本文不同，应连同 PRD 的第 11 章 Q1 一并讨论后修正。
4. **情感标签中，困难样本为人工给定，简单样本来自生成时的隐藏标签**。
   后者是可靠的——生成器明确知道自己写的是哪一类情绪表达。
